### 🐍 HYDRA / Agent Runtime District

The flagship direction is no longer a collection of isolated AI tools.
The target is a **controlled multi-agent runtime**: orchestration, workers, model routing, durable state, evidence, operator control and cloud execution.

```txt
DIRECTION:
operator intent
→ orchestrator
→ specialized workers
→ evidence
→ verification
→ synthesis
→ controlled action
```

Core lanes include HYDRA / Hermes runtime work, coding-agent orchestration and durable agent execution.
Private runtime work stays private; public repos below expose the reusable building blocks and proof systems.

### 🧾 Proof Runtime District

[`agent-proof-runtime`](https://github.com/HazEOskA/agent-proof-runtime) is the proof boundary for autonomous AI work.

```txt
MISSION MANIFEST
→ controlled agent output
→ deterministic acceptance
→ event evidence
→ Proof Bundle
→ independent verifier
→ operator verdict
```

The runtime is intentionally proof-driven: agents may propose work, but they do not get to declare their own execution trustworthy.

### ⚙️ Execution Force District

[`osa-execution-force-skills`](https://github.com/HazEOskA/osa-execution-force-skills) is the canonical skills/control-plane repo.

Current stable line includes versioned skill packages, registry compilation, permissions, evidence ledger, typed rollback, installer/runtime adapters and operator panel.
Runtime v2 / resolver work is the active next layer — focused on making skill selection and execution behavior real, not decorative.

### 🧬 Michael Angelo / Agentic City District

[`michael-angelo-pro`](https://github.com/HazEOskA/michael-angelo-pro) and [`angelo-agentic-city`](https://github.com/HazEOskA/angelo-agentic-city) explore a durable autonomous-agent kernel with:

```txt
Durable Mission Runtime
+ Safety Gates
+ Cortex Model Fabric
+ Hermes isolation
+ Atelier Live observability

```

This is the city moving from “agent demo” toward **runtime behavior, recovery and observability**.

### ☁️ Cloud Control District

[`osa-cloud-workspace`](https://github.com/HazEOskA/osa-cloud-workspace) is the Google Cloud control-plane lane.

```txt
GitHub = source
Google Cloud = runtime / infrastructure
Cloud Build → Artifact Registry → Cloud Run
ADC + user-managed Service Account
Evidence before status
```

The cloud direction is **Google Cloud first**: deployable workloads, controlled service identities, observable runtime state and explicit infrastructure boundaries.

### 🧠 Brain Lab

It is R&D — not a marketing claim and not treated as finished infrastructure.

Every serious project must answer:

```txt
What problem does it solve?
What is the source of truth?
Who or what may execute actions?
What is already verified?
What evidence proves it?
What remains UNKNOWN?
What is the rollback path?
What changed in the last session?
What is the next smallest task?
```

Rules:

```txt
NO FAKE CERTAINTY
NO INVISIBLE WORK
NO “DONE” WITHOUT PROOF
NO UNCONTROLLED REPO DRIFT
NO AGENT ACTION WITHOUT A CONTRACT
NO DEPLOY WITHOUT VALIDATION
UNKNOWN IS BETTER THAN INVENTED
```
